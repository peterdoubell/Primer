# Experimental pelvic mesh interpretations

The original [CVH5 source](cvh5-pelvic-source-review.md) has an experimental decoder for all 47 RHAdobeMeshResource geometry resources. Candidate arrays contain 341,454 positions and 688,510 triangles, with every resource payload accounted for and every source model-node name and native transform retained. Coordinate/index ranges, native quantization controls, encoded span hashes and candidate-array hashes are explicit. Source U3D bytes remain unchanged. No position is fitted, smoothed, welded or repaired.

The format reference is Adobe Developer Support's *U3D Supported Elements*, Acrobat 8.1 SDK, April 2007, recovered from an [archived original publisher URL](https://web.archive.org/web/20160621183205id_/http://www.adobe.com/content/dam/Adobe/en/devnet/acrobat/pdfs/U3DElements.pdf). Its 49-page snapshot has SHA-256 `307b3ede9b9f57d6b970b28ba49383467ce37fac5f4f6eda564da604c5d54916`. The document stays in ignored research staging; only provenance is retained here. This format reference is not a clinical standard.

An independently implemented ECMA interval reader agrees with a pinned local arithmetic reference on the candidate arrays across all resources. That verifies a narrower arithmetic component: both runs share the experimental RH layout/UIC1 interpretation. It does **not** independently verify the complete decoder, UIC1 history bootstrap, anatomy or topology. No third-party decoder code is redistributed. Published integer/cube examples and malformed-span rejection tests are retained.

Several format questions remain explicit holds. Actual buffers use widths and material/normal layouts that differ from incomplete SDK examples. The UIC1 history initialization is not independently confirmed. The original candidate files retain Type-3 normal payloads opaque. A [separate normal interpretation](cvh5-normal-interpretation-review.md) now retains experimental angle/vector arrays and held-out direction checks; verification remains unfinished. Source materials are not restored in the review figures. Precompression authoring samples cannot be recovered from quantized coordinates. Candidate boundary, nonmanifold and zero-area findings therefore cannot automatically be attributed to source geometry defects.

Six inspected sheets show all 47 candidate resources and every candidate triangle. Review colour and shading derived from candidate triangle geometry are display choices. No encoded source normal, biological colour, clinical axis, registration or patient-specific tissue accuracy is inferred. Native resource coordinates retain the source's declared 0.001-metres unit scale, with no extra scale multiplier; node transforms remain available without claiming source-section alignment.

Candidate arrays are a basis for further codec, source-correspondence and anatomical review. All resources retain `decoder_interpretation_verified=false`; normal-attribute, UIC1, registration and clinical holds remain. No runtime model or structure-coverage promotion is granted. Full radiology counts and rights counts are unchanged, and the original CC BY attribution and source correction continue to apply.

Reproduce with `python -m tools.anatomy_sources.review_cvh5_candidate_geometry --source docs/cvh5-pelvic-source-review --output docs/cvh5-candidate-geometry-review`, then `python -m tools.anatomy_sources.render_cvh5_candidate_geometry --output docs/cvh5-candidate-geometry-review`. These commands preserve experimental interpretations; successful reproduction is not decoder or clinical approval.

The [history sensitivity audit](cvh5-uic-history-review.md) now tests four initial histories on every applicable resource. Only the retained interpretation passes all 40 UIC1 resources; range-passing alternatives can still alter many faces. This is additional numeric evidence, not independent encoder provenance or clinical approval.

The [scene review](cvh5-scene-review.md) now retains source hierarchy, world placements, raw appearance bindings and separate PDF skin controls, enabling whole-pelvis relationship review without granting clinical or full-renderer equivalence.
