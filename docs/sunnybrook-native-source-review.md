# Sunnybrook native cine and original LV model evidence

The [primary Sunnybrook dataset](https://www.cardiacatlas.org/sunnybrook-cardiac-data/) supplies 45 mixed-pathology cases, original manual contours and fitted left-ventricular finite-element models. Its dataset and derivatives are CC0 1.0 Universal. The original archive licence and README are retained here; CAP software licensing is a separate question. Attribution: Radau P, Lu Y, Connelly K, Paul G, Dick AJ, Wright GA, “Evaluation Framework for Algorithms Segmenting Short Axis Cardiac MRI”, MIDAS 2009, <http://hdl.handle.net/10380/3070>.

This packet selects the original mapped case **SCD0000101 / SC-HF-I-1**, source category heart failure with infarct, male, age 53. The contour folder spells the original identifier `SC-HF-I-01`. Category and historical inclusion thresholds are source metadata, not a new diagnosis, a current universal threshold, independently measured EF, or independently demonstrated LGE.

## Actual source evidence

- Complete first-party DICOM batch 1 archive acquired: 433,585,535 bytes; SHA-256 `708ce04db1ac33948a00b9052d44e9548c6807121a4841f4c35080d6db127b72`. This is a local acquisition hash, not a publisher-supplied checksum. ZIP CRCs checked for extracted members.
- All **360** original model image references match exact native SOP and series UIDs among **1,047** case DICOM members. Each referenced 256×256 signed 16-bit pixel buffer agrees with independent little-endian scalar decoding. No source pixels or UIDs were repaired.
- **18** original planes (6 long-axis, 12 short-axis) each supply **20** distinct pixel buffers with increasing original trigger times and unchanged per-plane orientation/position. Nominal intervals differ between planes; these are not simultaneous 4D acquisitions of one heartbeat.
- All **20** original `.exnode` phases, their XML mapping, original `.exelem` and **33** manual contour files are retained byte-identically. XML frame 0 maps to source phase file 1. All 40 prolate nodes per phase retain λ value/three derivatives, μ and θ; focal length 35.8171. The XML interval `0.05` is retained without reinterpreting it as milliseconds.
- All **16** original volume elements retain eight source node IDs and 40 scale factors each. λ uses cubic Hermite × cubic Hermite × linear Lagrange; μ/θ use trilinear Lagrange, with **decreasing-in-xi1** angular modification for θ. No ordinary polygon interpolation or new surface has been substituted.

`native-cine-linkage-review.json` includes the allowlisted geometry, source pixel/file hashes and exact image references. Original DICOM UIDs contain leading-zero components, and one series UID spans SAX, LAX, perfusion and other folders. The source defect is explicit: series UID alone is not a grouping key. Pixel spacing and geometry are declared source metadata, not independent scanner/phantom calibration.

`native-sa6-20-frame-context.png` and `native-plane-phase-context.png` show matched original pixels with a recorded display window and nearest-neighbour display. They are contact sheets, not raw volumetric/cine viewers or quantitative validation. Additional perfusion/tissue acquisitions remain outside the current decoder review. The initial parameter report's `native_image_linkage_verified=false` records the earlier stage; the separate native linkage report supplies the subsequent exact UID/pixel evidence. Neither validates model geometry.

Its matrix reader/transpose convention and xi3_0 epicardial / xi3_1 endocardial graphic selection are recorded with source-file hashes in `cap-model-reader-code-review.json`. That code was inspected, not executed, and is not proven identical to the 2012 conversion revision. Independent Zinc/Cmgui evaluation, native-plane registration, angular seam/apical/basal checks, original contour pixel/index/phase conventions and comparisons remain required. At the initial parameter-preservation stage no surface had been generated. The subsequent numerical evaluation and source-surface sampling below supersede that stage for evaluated geometry; contour lofts, replacement anatomy, function measurements and clinical approval remain absent.

The fitted LV model and sparse manual contours cannot fill complete RV, valves, chordae, vessels, pericardium, scar/maps, all myocardial layers or disease-specific anatomy. Full reporting structure requirements remain active. Nothing in this packet is promoted into runtime or credited as verified leaf coverage.

## Subsequent numerical model evaluation and image-plane conflict

All 20 original phases and all 16 source volume elements have now been loaded successfully by **cmlibs.zinc 4.2.1**. Original nodes must be loaded before the element file for this import. A separate scalar implementation of the source Hermite/Lagrange basis, angular decreasing-in-xi1 rule, prolate conversion and serialized-matrix transpose agrees with Zinc at **34,560** points. Maximum patient-coordinate discrepancy is approximately **2.84 × 10⁻¹³**. This demonstrates numerical reproduction of this original model, not anatomical fit accuracy, source naming, current diagnostic criteria or clinical function. Original inputs are byte/hash checked before evaluation. The publisher-verified wheel hash and MPL 2.0 package metadata are in `zinc-evaluator-provenance.json`; the evaluator stays in ignored research storage.

The model XML overrides image origins for **nine planes / 180 images**. Exact original XML and DICOM positions are preserved separately for all 360 images. Shift lengths range from about 1.04 to **5.74 source-declared mm**. The inspected CAP loader explicitly applies XML image-position overrides. Identical SOP/series references therefore do not mean that model fitting used the unadjusted DICOM geometry. No additional registration, plane shift or coordinate correction was applied here.

Both original xi3 faces are sampled for **all 20 phases** at 32 subdivisions per source element axis. Each face has 17,424 float64 vertices and 32,768 triangles, with element patches kept separate and source angular rounding retained. No seam welding, fitting, smoothing, decimation or new basal cap was applied. Both triangle barycentres per cell were compared with the original curved FE face; maximum sampled deviation is approximately **0.0264** in source-declared physical coordinates. This is sampling evidence, not a global Hausdorff bound, true tissue-wall accuracy or independent millimetre calibration. `source-surface-sampling-review.json` binds the original model inputs, evaluation proof, shared uint32 triangles and all 40 position files.

**Surface-role conflict remains unresolved.** The inspected CAP code selects xi3_0 for its epicardial graphic and xi3_1 for its endocardial graphic, but all **11,520** checked same-parameter pairs have a smaller lambda for xi3=0, and the original MRI overlays visibly show that face inside xi3=1 in this converted case. The inspected code revision is not proven identical to the 2012 conversion. This discrepancy is recorded, not repaired by relabelling source geometry or assuming the code labels are clinical truth. All derived graphics use neutral **xi3=0 / xi3=1** IDs and keep clinical tissue roles unassigned pending original contour/converter evidence and specialist validation.

The two `native-model-plane-comparison-frame-*.png` sheets compare unchanged native pixels with the same original fitted surfaces in unadjusted DICOM and original XML-adjusted planes for LA2, SA6 and SA8 at frames 0 and 10. `original-fe-surface-phase-context.png` displays those two original model phases in source patient coordinates. These static views and source phase samples do not establish complete cine review, source fitting accuracy, contour conventions, closed manifold topology, wall volume, EF or lesion geometry. Source face IDs and phase IDs remain original; full reportable structure coverage and clinical/commercial validation remain outstanding.

## Original author contour linkage and source surface identity

The dataset author's [original distribution](https://sourceforge.net/projects/cardiac-mr/files/) and supplementary protocol were inspected. The CIM converter at SourceForge revision `b2ba32` supplies an element template **byte-identical to this case after substituting the explicit focal placeholder with 35.8171**. Raw CIM inputs are absent, so the original conversion has not been replayed and the exact deployed converter revision is unproven. Source-code files remain in ignored research storage; their URLs/hashes and observations are recorded rather than redistributing software under the dataset's CC0 grant. The author evaluation README says LGPL v2.1, while its included lesser-licence header says version 3; that discrepancy is retained, not silently resolved.

The original format document identifies `i` as inner/endocardial, `o` as outer/epicardial, and optional `p1`/`p2` as the two largest papillary muscle contours. It explicitly defines zero at the top-left corner and x/y in pixel units. The manual protocol includes papillary/trabecular tissue within the source LV-volume contour and separately includes supplied papillary contours in mass calculations. It supplies outer contours in diastole, **not systole**. Those are historical dataset conventions, not universal current clinical rules. The raw coordinates are unchanged; ambiguity between corner coordinates, pixel centres and the historical MATLAB plotting convention is handled through explicit sensitivity comparisons.

Case SC-HF-I-01 belongs to original **DICOMPart3**. The completed Part1 archive had publisher SHA-256 `851f08232641a3fd17821b0f07ca74e86c31c15fba3fcb259c6b32c0e7f36aac`, but its fifteen cases exclude this case and were not used as its source images. All **240 complete SC-HF-I-01 original SAX DICOM members** were acquired from Part3 through checked HTTP ranges, stable ETag and ZIP CRCs. The full Part3 archive is 208,345,315 bytes; its published SHA-256 is `b0a54336316e09e801e8175edaa01a75c108bcfb87be7cacc16d5d044e01bd38`. **The full Part3 archive hash has not been verified**, because only its directory and complete selected case members were acquired.

Every original SAX pixel buffer and its position/orientation/spacing agree exactly with the corresponding CAP image; original pixels also agree with independent scalar decoding. Every original SOP UID differs from its redistributed CAP SOP UID. Exact pixel/geometry correspondence and original filenames therefore establish the link that UID equality could not. All **33** original manual files now match exact original `IM-0001-####.dcm` filenames, rather than guessing from renamed `IM-0003` filenames. The one-based source annotation phases are **8 and 19**, corresponding to model frames **7 and 18**. There are 18 inner, 9 outer, 3 p1 and 3 p2 contours; all outer contours occur at source phase 19. The contour perimeter step and closing gap never exceed approximately 0.7071 pixels. No points were closed, smoothed or repaired in the source files.

Both model faces were compared with all **27** inner/outer contours under native and original XML-adjusted plane origins, and offsets 0, 0.5 and 1 between raw contour coordinates and native pixel-centre coordinates. Inner contours select xi3=0 in **108/108** comparisons; outer contours select xi3=1 in **54/54**. This supports **xi3=0 as the source LV inner/endocardial boundary and xi3=1 as the source outer/epicardial boundary for this converted case**, despite the inspected CAP renderer's opposite names. It is source semantic correspondence, not clinical geometry approval. The old source-code claim is retained as a conflicting claim; neither the original source model nor its files have been relabelled or repaired.

Mean source-vertex distances to the corresponding fitted-face intersection segments vary across tested origins: roughly 0.86–3.37 pixels for inner contours and 0.55–3.41 for outer contours. This is a one-way nearest-segment diagnostic, **not** the original author's perpendicular-normal/APD benchmark or an accepted clinical accuracy threshold. Absolute pixel-centre calibration, complete native/fitted spatial registration, source annotation/fitting quality and anatomical review remain pending. The sparse papillary traces do not supply complete papillary volume, tissue interfaces or chordae.

`original-contour-model-phase-08-context.png` and `original-contour-model-phase-19-context.png` show the actual annotated phases and supplied papillary traces alongside both original fitted faces, with unchanged native pixels in native and original fit planes. These sheets were inspected. No missing manual outer systolic contour, new papillary geometry, EF or mass was fabricated. The red systolic outline is an intersection of the supplied fitted model, not a manual outer annotation. Whole reporting-structure coverage remains incomplete and no runtime or verified-leaf promotion is granted.
