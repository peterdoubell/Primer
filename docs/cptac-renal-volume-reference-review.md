# Native renal CT volume reference — 2026-10-05

A standalone interactive 3D source-volume viewer now supports CPTAC-CCRCC case C3N-03018, acquisition 1, using every original acquired voxel. It is an offline source review artifact, not a segmented kidney model, anatomical approval or clinical examination. The reader is not changed or deployed by this work.

The exporter verifies the original CT archive against its preserved SHA-256 and the selected original source/rights contract. All 850 source DICOM objects remain in the original archive. Acquisition 1's 417 frames are selected explicitly and sorted by actual source position; acquisition 2's 433 frames are excluded from this derivative rather than interleaved or deduplicated. Every selected frame's orientation, dimensions, HU conversion, pixel spacing, acquisition time, slice thickness and original spacing tag is checked.

All 109,314,048 native voxels (417 × 512 × 512) are retained, with no spatial crop, resampling, decimation, smoothing or annotation overlay. Signed 16-bit little-endian HU encoding is exactly reversible to source stored values using the original slope 1 and intercept −1024. Thus the value representation changes while source information is conserved. The export has 218,628,096 uncompressed bytes and 104,568,826 compressed bytes; full compressed/uncompressed SHA-256 and 417 plane hashes are preserved. Gzip decompression was read back exactly.

Original source spacing is 0.976562 × 0.976562 mm in-plane. Source positions advance uniformly by 0.625 mm, matching the slice-thickness tag, while the original SpacingBetweenSlices tag says 2.5 mm. These fields remain separate. The viewer uses observed acquired positions for physical aspect and does not overwrite the conflicting tag or fit the volume to an isotropic cube. Original source LPS origin/orientation is retained.

The viewer validates pinned original/archive/selection and decoded-volume identities before display. It uploads the full 512 × 512 × 417 integer texture with nearest-value access and no silent hardware downsampling. Five source probes were checked both on CPU and by exact integer GPU framebuffer readback. This verifies tested GPU values and indexing, not a complete second GPU checksum or anatomical accuracy. Unsupported full-resolution upload/readback fails explicitly.

The display provides native orthogonal planes in 3D, sampled nearest-value maximum-intensity projection and a HU transfer-function volume. Rotation, window/centre, source-plane indices and zoom retain the source grid and physical proportions. Projection/transfer-function settings are display choices and do not classify tissue, establish perfusion or guarantee that every stored voxel is simultaneously visible. The volume is not an extracted surface mesh, and no original tumour contour is overlaid or relabelled into a whole-organ segmentation.

24 focused native-volume, acquisition, volume-convention, source-selection and contour regressions passed. The local full export was decompressed and every source plane hash/probe checked. Browser verification loaded all source bytes and passed CPU/GPU probes, source-plane display, projection and transfer-function switching. The initial mode change event did not redraw under browser automation; adding change handling corrected it. Desktop 1200 × 900 and mobile 390 × 844 screenshots were inspected; no page overflow or application errors were observed. Browser/server sessions were closed.
