# Original cardiac CT and source-interface inspection

Review date: 2026-10-14. This addition supplies a concrete LV-myocardium source and four chamber-region interfaces. Complete cardiac reporting anatomy and whole-Primer clinical/commercial readiness remain unproven.

The original TotalSegmentator v1 s0028 CT and five original masks come from [Zenodo record 6802614](https://zenodo.org/records/6802614), DOI 10.5281/zenodo.6802614, CC BY 4.0. The retained Zenodo metadata contains the license grant. Attribution: Jakob Wasserthal and colleagues, *TotalSegmentator: Robust Segmentation of 104 Anatomic Structures in CT Images*, DOI 10.1148/ryai.230024. `acquisition.json` preserves exact archive-member names, range hashes, CRC32 and original file hashes. The complete archive MD5 is not claimed verified.

Published [cardiac methods](https://pmc.ncbi.nlm.nih.gov/articles/PMC10980695/) identify the TotalSegmentator cardiac outputs as LV myocardium and chamber volumes. The original `heart_myocardium` name is retained, and its role is explicitly limited to LV-myocardial context. The other four labels do not establish myocardial walls, appendages or complete valve-defined blood pools. No RV/atrial-wall, coronary, mass, valve, pericardial, MRI-signal, functional or normal-atlas coverage is granted.

The source case is a 60-year-old female, institute C, training split, with a neck/thorax/abdomen/pelvis CT. Its published grid is 299 × 299 × 394 after 1.5 mm dataset resampling. Original signed-int32 CT samples and all binary-mask samples remain unchanged. The browser keeps a zero-copy view of the decoded CT and losslessly bit-packs the five binary masks. Every one of the 176,119,970 original mask values restores exactly. Retained source buffers total 162,911,328 bytes instead of approximately 317 MB of dense CT/mask buffers; an extra 140,895,976-byte CT copy is also avoided. This bounds retained source buffers, not total browser heap or physical-device memory. NIfTI physical units are unspecified; the viewer presents source axes and values without independently asserting patient orientation, HU calibration or native scanner DICOM. Contrast phase, cardiac phase and pathology/normality approval remain unspecified.

The v1 CT and existing v3 s0028 CT share shape and sform but differ in 11,945 samples, all outside these five original cardiac labels. They remain separate source images and metadata. Shared case identifiers do not grant cross-version or current-patient registration.

All five complete 0.5 mask interfaces are retained: 86,072 triangles, including 29,012 for LV myocardium. There is no smoothing, padding, capping, fitting, component removal, relabelling or repair. Source float64 positions are recentered for float32 display and restore byte-identically on these inputs; original uint32 triangle indices are retained. Area-weighted normals are display derivatives. A closed label interface is not independent proof of physiological boundary accuracy. Original extraction positions/indices are preserved alongside the display buffers in `surfaces/`; `source-review.json` binds their identities.

The companion is appended to thoracic ultrasound, MRI cardiomyopathy, coronary CT and cardiac-mass reporting references and shared lessons as CT anatomy context. Existing cardiac reporting orientation/anatomy guides remain available, and inspecting this separate source does not fill current-patient findings. The source registry is `data/radiology/cardiac-native-inspector.json`; seventeen runtime files are mirrored here. Authenticated authored resources are private and not cached. Registered original payloads use fixed static delivery paths in production, with no fallback for present wrong bytes, symlinks, nonregular files or unknown paths.

Fresh `browser-proof.json` covers 90 entire-canvas RGBA comparisons, twelve actual GPU buffer/draw cases and fourteen further interactions at 1440/390 px. The implementation and manifest hashes bind the tested resources. Every browser CT/mask payload and every uploaded position/normal/index buffer matches its declared source or display derivation. Source failure hides stale contents and retry recovers. Representative captures are in `evidence/`.

`integration/local-reader-proof.json` covers sixteen authenticated actual reader cases: four reports and their shared lessons at two widths. All original CT/mask payloads match, all five interfaces remain available and all 86,072 triangles are drawn together. All seventeen delivered file bodies match stored originals or their explicit HTTP-decoded representations; altered/encoded paths are rejected and anonymous access requires authentication. Existing reporting-guide modes remain available. The fixture used only a synthetic learner and isolated database, with no production learner writes or production-authenticated reader claim.

`integration/runtime-inverse.json` records exact literal reversals of five shared files for frozen prior evidence. All prior source/decoder bindings and review hashes remain unchanged; unknown edits stay rejected. The separate UI-refresh record permits only the specified wrapper addition and does not extend anatomical approval. The earlier prototype proofs are retained separately and are not substituted for the current reader evidence. The original prototype manifest is retained separately. Operational publication flags are omitted from the runtime source manifest; deployment status belongs in the release receipt.
