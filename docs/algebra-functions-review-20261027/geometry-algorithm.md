# Algebra graph geometry

`PrimerAlgebraFunctionsSpatial.scene(model, options)` consumes the core's actual rational polynomial coefficients, line equations, named points and signed construction segments. It returns mathematical coordinates. The spatial renderer maps them to a plane at z=0 using one gain for x and y; it adds no mathematical third variable or unrelated surface. Oblique projection does not preserve screen angles, so perpendicularity is judged in the frontal 2D graph or exact equation ledger.

For a polynomial segment `[a,b]`, binary floating endpoint coordinates are converted to exact rational values. Coefficients retain the core's exact numerator/denominator values. The polynomial is converted to Bernstein coefficients on that interval using BigInt rational arithmetic. Their exact convex hull supports exclusion of an entire interval when it is strictly above or below the window. Each omitted interval carries both outward-rounded floating bounds and the exact rational hull bounds; only the exact bounds decide exclusion.

The Bernstein coefficients of `f(x) - endpoint_chord(x)` bound the vertical interpolation error throughout the interval. Conversion error of the endpoint ordinates is measured against their exact rational values and rounded outward. Clipping roundoff is also bounded by comparing the actually emitted clipped endpoints against the original chord with exact rational arithmetic. Because the difference between those two chords is affine, its maximum absolute difference occurs at an endpoint. The sum bounds the entire emitted segment. The geometry checker verifies that bound directly against Bernstein coefficients of the source polynomial minus the actually emitted chord, using Python Fraction arithmetic.

A chord outside the window is not evidence that the polynomial is absent between endpoints. Such intervals are subdivided while their exact Bernstein hull still overlaps the window. If binary coordinate resolution prevents deciding a boundary contact, the result is explicitly `boundary-uncertain`; it is not labelled outside-window. A sampling budget or unresolved requested precision produces an explicit error, not a silently coarse curve.

Line/frame intersections and corner membership use exact rational comparisons. Numeric endpoints carry their exact rational positions and conversion-error bounds. Named point markers retain exact/approximate status, exact coordinate text where supplied, and all mathematical IDs. Exactly coincident markers share one glyph; nearby unequal markers are not merged by an epsilon.

The default overview includes supplied source landmarks and uses equal scales. `chartFocus` and `chartRadius` are separate display state, stripped before core arithmetic. A focused chart centres on the chosen actual graph point and takes a requested half-width in both coordinates. Radii from 1e-12 through 1e12 are supported where coordinates can represent the window. Collapsed, nonfinite or precision-lost windows are explicitly rejected. The half-width may lose no more than 1/4096 to coordinate rounding, matching the default display-tolerance scale; the radius is never silently widened. Focused frame labels use centre-plus-offset notation to avoid rounding different endpoints to identical absolute labels. The note retains the full centres and absolute bounds.

The family's mathematical controls remain in the shared workbench. Its normalization strips display fields, invokes the exact core, then validates display state separately. Mutable copies of accepted state allow the existing renderer's state bus to update both views. Camera movement preserves mathematical and display parameters. The generic renderer's explicitly named Reset model operation is a model reset, not a camera operation.

The local numerical checker is an implementation check, not a replacement for independent mathematical review. The standalone browser checker verifies every projected segment and marker against the emitted 3D primitives, all labels and page bounds at 390/1440 widths, and the seven camera controls across presets and representative focused views. The actual lesson/assessment/browser integration is verified separately by the parent task.
