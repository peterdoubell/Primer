# MedSeg source CT, version 2 case 1

This dedicated source study retains the original publisher CT and nine-code mask pair, not a generated Couinaud prediction. It is different from s0028 and the separate MR reference. The MedSeg publisher's label key explicitly separates codes 4 (Segment 4A) and 5 (Segment 4B). No combined segment-IV mask or completion claim is created.

## Native source and rights

`publisher-metadata.json` is the annotation owner's own Figshare API record for DOI `10.6084/m9.figshare.13643252.v2`. The owner page links this exact release. It credits MedSeg, Håvard Bjørke Jenssen and Tomas Sakinis, says the segmentations were done by MedSeg, and declares CC0. It identifies the CT source as the Medical Segmentation Decathlon. The upstream MSD organisers and their primary Nature Communications dataset paper explicitly permit redistribution and commercial use under CC BY-SA 4.0. The CT and CT-derived adaptations retain those terms; the annotation publisher's CC0 field does not replace the upstream CT licence. Both provenance chains are named in the viewer, manifest, rights review and attribution record.

One selected pair was obtained by validated HTTP 206 byte ranges from the publisher's ZIP files. `acquisition.json` records the exact public file IDs, provider-reported archive checksums, ZIP member CRCs, requested ranges and actual selected-member SHA-256 hashes. Whole-archive MD5 values are publisher metadata, not falsely claimed to have been recomputed from partial downloads. Only the image1/mask1 pair was acquired; no image cohort was downloaded. The original MSD case number, demographics, diagnosis and phase are not supplied in this MedSeg collection. Version 2 explicitly replaced its case 1, so the version is retained.

The original NIfTIs are included unchanged. Both are float32, 512 × 512 × 47, with identical qform/sform (code 1, RAS+), mm units and sampling of 0.9765620231628418 × 0.9765620231628418 × 5 mm. Their slopes/intercepts are 1/0. Every sample is an integer exactly representable by the two-byte CT or one-byte label transport. Conversion back restores the complete original float32 byte arrays, including their sample hashes. This is lossless re-encoding, not source resampling or rounding. The original DICOM calibration is not supplied; the viewer uses “stored CT value”, not an unsupported HU claim.

## Display and geometry

Full native sections and all nine original labels remain available in three source-index planes. Radiological mode reverses the appropriate horizontal source direction using the aligned RAS affine; unflipped index order is available. Physical aspect ratios retain the original 5 mm slice spacing. Selected-label context cropping changes only the display field, with a margin of at least 12 mm on each displayed axis. Pixel clicks invert cropping/orientation and expose original label code, intensity and header RAS coordinates. Header coordinates do not establish registration to the current patient.

Every source mask is nonempty and avoids the acquisition boundary. The nine unsmoothed 0.5-interface meshes retain all components, have closed two-face edges and outward winding, and contain 341,310 triangles in total. Mesh coordinates are native index × native pitch; their source translation is retained separately in the affine. Lewiner triangulation approximates the sampled interface; it is not an exact continuous anatomical boundary. Volume readouts use source cell counts and the native pitch product, not a claim of measured functional territory.

`source-comparison.json` is generated by the independent verifier, which does not import the packaging implementation. It checks all 12,320,768 CT and label cells in all 512 bricks, the original float32 byte reconstruction, every focus against the original code array, native-plane hashes and areas, and every mesh's hashes, indices, source-boundary-cell membership, closed edges and winding. `package-review.json` is the separate generator receipt.

## Stable route contract

`/app/anatomy/medseg-liver-001/index.html?segment=4a&plane=ij&display=outline&focus=label&exam=ct.liver-mass#ct`

- `segment`: `1`, `2`, `3`, `4a`, `4b`, `5`, `6`, `7`, `8`. These map to original codes 1–9 and verbatim publisher names. `4` is deliberately not a combined-IV alias.
- `plane`: `ij`, `ik`, `jk`; `display`: `outline`, `raw`, `map`; `focus=label` selects a verified interior source voxel.
- `exam`: return-only whitelist `ct.liver-mass`, `ct.liver-lirads`, `ct.liver-lirads-calculated`, `ct.chest-abdomen-pelvis`. It does not change the source data or create a patient association.
- Anchors: `#ct` source CT panel, `#map` native viewport (use `display=map`), `#surface` selected source-mask 3D panel.

A discoverable “Compare all nine regions in 3D” link points to the separately authored `/app/radiology/liver-segment-assembly/index.html` with the selected canonical `segment` and return-only `exam` in `URLSearchParams`. It is hidden while no valid source segment is selected. The assembly assets and report links are maintained separately.

Malformed, duplicated or incompatible target parameters leave the source segment unselected with recovery feedback. All four return URLs come from fixed app-owned values. No report content or patient record is written by the viewer. The existing shared native reader, bounded fetch pool, integrity checker and mesh renderer are reused.

## Reproduction and checks

The fixed-path packager rejects any originals whose SHA differs from the selected publisher pair: `python tools/anatomy_sources/package_medseg_liver_001.py`. It requires the existing authoring environment's nibabel, NumPy, SciPy and scikit-image. `write_delivery()` may be imported to refresh the UI delivery hashes without regenerating scientific data.

`python tools/anatomy_sources/verify_medseg_liver_001.py` reproduces and checks the independent scientific receipt; `--write` regenerates it. The source and native UI are tested by `tests/test_medseg_liver_source.py`; older torso and packed-form inverse tests retain their original pins and project this later delivery layer first. The only shared runtime delivery changes are the fixed-owned atlas allowlist/iframe CSP and static gzip hosting rules. The report renderer, torso viewer and CAP anatomy inventory are not changed here.
