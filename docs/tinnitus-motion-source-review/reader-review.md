# Original tinnitus angiographic display clips

The tinnitus Images and motion tab now offers two source clips associated by their original captions with the published right sigmoid-sinus dAVF Figure2 case. Supplement1 is a processed segmented/inverted CT angiographic MIP display; Supplement2 is DSA projection context, with selective external-carotid injection supplied by the source legend. Neither is a new patient's acquisition, a complete CT volume/registered mesh, calibrated flow/pressure measurement or new causal/shunt-grade determination.

Each original AVI contains12frames at encoded3fps, spanning presentation times0 through11/3seconds with encoded4secondduration. These are display chronology, not independently verified acquisition interval, injection clock, pulse/ECG synchronization or native intermodal registration. Patient ages and sex are unsupplied. The original MS Video1/RGB555LE files and native per-frame/sequence hash evidence remain preserved.

A direct RGB555LE-to-planar encoding changed decoded RGB values despite using a lossless encoder. That candidate was rejected. The accepted browser transport starts from the independently verified RGB24 source decodes, then uses lossless VP9/gbrp. Every decoded RGB frame matches exactly across original and browser files, without crop, scale, contrast adjustment, temporal interpolation or added/removed frames. Browser timestamps are rounded onto the container millisecond lattice by at most1/3000second; original presentation times are displayed separately.

A bounded RIFF/AVI reader checks declared dimensions, stream rate/start/count, bitmap codec, ordered frame chunks and index offsets. It rejects extra tracks, unsupported continuations, inconsistent clocks, crops/scales and malformed sizes/indices. Original sector-alignment trailers, including nonzero source bytes, are preserved outside the declared RIFF data and never interpreted as extra frames. This establishes container chronology; it is not independent image decoding or physiological validation.

The larger movies are delivered by the existing registered static host. Runtime validation uses actual local file hashes/contracts, or, only in hosted missing-file mode, the committed release inventory with matching hashes and contracts. CI independently regenerates that inventory from every actual original/transport file. Missing local files outside hosted mode, mismatched hashes, modified timestamp lists/counts/dimensions or false anatomical coverage are rejected. Source PNG and mesh workflows are unchanged.
